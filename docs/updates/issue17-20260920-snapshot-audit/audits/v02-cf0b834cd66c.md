## Requirement and final released behavior

The native XPU GDN entry point requires request-indexed metadata lengths to equal its scalar request counts. Shared graph metadata may have more rows than the live request group. Passing those larger arrays fails native shape checks before useful execution. Request counts must stay distinct from token counts and speculative state-column capacity.

The commit adds only 22 lines in `vllm/_xpu_ops.py`, including its comment. Its effective behavior is:

| Metadata | Length passed to the native operator |
| --- | --- |
| `non_spec_query_start_loc` | `num_prefills + num_decodes + 1` |
| `non_spec_state_indices_tensor` | `num_prefills + num_decodes` |
| `spec_query_start_loc` | `num_spec_decodes + 1` |
| `spec_state_indices_tensor` | first dimension `num_spec_decodes`; retain all rollback columns |
| `num_accepted_tokens` | `num_spec_decodes` |

Optional `None` inputs remain `None`. Slicing changes local views, not metadata ownership, padded backing storage, token-index arrays, projected data or output tensors. Existing `.contiguous()` handling of the non-spec state indices predates this fix.

The relevant hardware/workload is native Qwen GDN on Intel XPU, including Brutus/Arc Pro B70 hybrid target inference and retained MTP speculation. K4V2 compresses attention KV, not this recurrent GDN state. Excluding graphs from initial DFlash2/V2 qualification does not retire the existing adapter requirement.

`git diff cf0b834c..2fdd9d71 -- vllm/_xpu_ops.py` shows all five slices survive unchanged. The only later changes in this file are v03's mixed ordinary decode/prefill predicate and native keyword. No release-only commit supersedes v02. I did not locate an original isolated GPU failure log during this bounded audit; the failure mechanism below is demonstrated by producer/consumer source contracts, not a claimed runtime reproduction.
