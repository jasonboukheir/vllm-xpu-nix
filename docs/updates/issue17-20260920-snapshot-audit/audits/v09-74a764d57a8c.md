# v09: explicit unquantized XPU cache dtypes

**Disposition: KEEP**, as an independent, narrowly scoped correctness fix.
Assigned commit: `74a764d57a8c3c2e6bc1376be0f9dfa122aed90f`; parent:
`3b6c822e8a4f56dc3904c7fce388a76dff4c7bdd`. The final released vLLM tip is
`2fdd9d71f6895379b0940a8f755b4c9095840558`, and the frozen target is
`e378275a8f20eac9e92212e4a1fee84ec5a31dc7`. The paired kernel target is
`da16a5595c105605bcd44b558c7933b934a05f85`, versus released
`2c39287deec5e59cc2656e6d4a6dce51a567c411`.

The requirement is correct explicit FP16/BF16 cache writes through native XPU
FlashAttention. At the parent, `vllm/_custom_ops.py:reshape_and_cache_flash`
passes the configured dtype string unchanged. The native writer rejects
`"float16"` and `"bfloat16"`, although its `"auto"` implementation supports
matching input/storage tensors. This prevents a valid explicit unquantized
cache from operating. It matters particularly for the pinned RedHat W4A16
Qwen checkpoint: changing the engine setting to `auto` can select the
checkpoint's FP8 cache scheme and invalidate an unquantized reference.

The patch translates only at the native call boundary, only for XPU and these
two explicit names. Before translation it requires **all four** tensors—key,
value, key cache and value cache—to match the requested dtype. This preserves
the native template's input/storage ABI instead of allowing reinterpretation
of incompatible buffers. It neither converts tensors nor changes the engine
configuration. CUDA/ROCm, `auto`, quantized strings and KVarN remain outside
the branch. FP16 model/BF16 cache conversion is intentionally unsupported.

The final old release retains this implementation unchanged: the entire
`_custom_ops.py` diff from v09 to the released tip is empty. Later commit
`2e010408b9713dca3de690f339ef46fbe72f090f` (v15) adds BF16 MTP draft admission
and twelve paged-attention reference cases to the same test file; it does not
replace or weaken the writer repair. Thus v09 is not a temporary workaround
superseded by the later mixed-cache integration.

At the frozen kernel target, `csrc/cache.cpp:reshape_and_cache_flash` dispatches
both contiguous and strided-head layouts through
`csrc/quantization/fp8/quant_utils.h:DISPATCH_BY_KV_CACHE_DTYPE`. That macro
accepts `auto`, `fp8`/`fp8_e4m3`, and `fp8_e5m2`, and rejects the two literal
unquantized names. Both files are byte-identical between old upstream kernel
base `e7f20cbc18d741419a84aa57178e1f1cc0b453da` and the selected target;
they are also unchanged at the released kernel tip. No native-side equivalent
exists in this pair. The registered `_C_cache_ops.reshape_and_cache_flash`
schema and XPU dispatch remain compatible; retaining v09 requires no paired
schema or kernel modification.

The selected vLLM call path also still needs the repair.
`XPUPlatform.get_attn_backend_cls` defaults ordinary FP16/BF16 attention to
FlashAttention. `FlashAttentionBackend.supported_kv_cache_dtypes` includes the
literal names, and `FlashAttentionImpl.do_kv_cache_update` passes
`self.kv_cache_dtype` unchanged. `fa_utils.py` binds the XPU writer directly to
`ops.reshape_and_cache_flash`; the upstream wrapper still immediately calls
the native operator. From old vLLM base
`51da0ca66c8065619c79e35dff97aa99aeaf5644` to the target, XPU selector logic
is unchanged: `8c1557a79c539ffe82d004d2a0c8d7b5e71159ce` changes docstrings,
and `78e84261ab2ffb691a8079d698d1f3f96ecb7635` changes sparse-GELU dispatch.
The `fa_utils.py` delta is only documentation formatting.

Two upstream alternatives provide partial coverage at different layers.
`852f567444cf8c206219edb7b2c42aec55fc41cf` preserves explicit cache choices
over checkpoint schemes in `Attention.__init__`; it already predates the old
base and does not translate native arguments. Likewise,
`53a20886752bdf8f26c4c5121458c514096da107` permits native dtype names in
`triton_reshape_and_cache_flash`; it also predates the old base. Explicit
`TRITON_ATTN`, float32 fallback, and automatic multimodal-prefix fallback use
that Triton writer and bypass v09. Switching every affected configuration to
Triton would change backend/performance policy rather than establish native
coverage. Encoder-only vision attention skips this cache update entirely.

The minimum residual is the original fourteen-line guarded translation plus
its two sparse-write tests. Keep it separate from the KVarN feature rather
than burying this independently useful native fix in v05/v10. No prerequisite
local commit is needed despite its historical parent. v15 consumes it when
selecting native BF16 draft attention; preserve v15's useful causal-reference
tests with that integration, without duplicating the writer guard. Preserve
authorship/sign-off during replay. No broad dtype alias helper, config rewrite,
second native implementation, or new kernel ABI is justified.

Validation observed in this audit is source/history inspection and successful
empty-diff checks described above; no GPU, model, build, or service was run.
The original test writes across page boundaries and sparse slots, ignores a
negative slot, checks exact stored values and untouched NaNs, and rejects a
mismatched value-cache dtype. Historical `docs/releases/xpu-v1.9.0.md` and
`benchmark-results/kvarn-k4v2/20260913T051252Z/capacity-scratch-package/installed-tests.log`
record 603 installed passes including both writer cases. The v1.10.0
`benchmark-results/kvarn-mtp-draft-cache/20260914T232612Z/metadata-repair-v1/gpu-installed-outcomes.json`
explicitly records these two plus all twelve later attention cases passing;
its companion log reports 62 total passes. These are released-stack evidence,
not qualification of the selected pair. The release retains six separate
NaN-padding attention diagnostic failures and a shared arithmetic semantic
failure; neither is fixed by dtype translation.

Pending final-pair validation should rerun both writer cases on the installed
package, cover the actual strided cache layout and each mismatched tensor,
and verify explicit configuration survives checkpoint resolution. Upstream
alone should fail the literal native-writer tests; the retained patch should
pass. Reuse the small causal references without creating a BF16 serving
milestone. Integrated V2 DFlash2 qualification must continue directly with
K4V2 for both caches, preserving MTP and vision; this fix supplies no compressed
draft geometry, lifecycle, capacity, or performance guarantee.
