## Requirement and final old behavior

The original failure is variation between otherwise identical, fixed-shape quantized projections. k01 requests `pattr.set_deterministic(true)` inside `oneDNN::dnnl_matmul_w4a16_int4`'s attribute callback in `csrc/xpu/onednn/int4_gemm_w4a16.h`. Its comment identifies floating-point global K-parallel accumulation as the strategy to avoid. The implementation applies to the existing BF16 and FP16 W4A16 paths, including symmetric scalar zero point and grouped asymmetric zero points; its regression tests specifically cover production BF16, group 128, packed symmetric INT4 with zero point 8.

The patch's nine exact-shape cases cover decode/prefill attention, GDN projections, and MLP gate/up/down shapes, with M=1, 107, or 162. They interleave different tensor handles at the same cached primitive shape, perturb allocations, and require bitwise equality on replay. Six additional cases compare M=4 with four M=1 calls. Their gate permits `atol=rtol=2*torch.finfo(bfloat16).eps` (0.015625) and records exactness separately. Fixed-shape determinism does **not** establish bitwise equality across different M, complete model determinism, or dequantized-reference accuracy.

The requirement still applies to the released Intel Arc Pro B70 / BF16-compute / compressed-tensors W4A16 target, documented in `docs/releases/xpu-v1.10.0.md`, and to issue #17's required symmetric group-128 W4A16 DFlash2 draft. Quantized draft dispatch remains integration work, but retaining this op-level behavior avoids weakening the already supported target path.

`git diff 8530de9... 2c39287... -- csrc/xpu/onednn/int4_gemm_w4a16.h tests/test_int4_gemm_determinism.py` is empty. The old-base-to-release path log contains only k01 for these files. Thus all later main and release-only commits preserve the full contribution; this is not a reverted workaround.

Those results use an older checkpoint/runtime and do not qualify a replacement for this release. There is no integrated replacement in the frozen call path. The target's existing `tests/test_int4_gemm_onednn.py` checks FP16 numerical accuracy against a dequantized reference; it contains no fixed-shape replay requirement and does not replace k01's BF16 repeatability tests.

## Minimum residual and dependencies

Keep the three-line implementation addition (comment plus `set_deterministic(true)`) and the existing focused test file as one commit. No upstream portion can currently be subtracted from that implementation. No op schema, Python signature, packed-weight layout, serialization, or cross-repo ABI changes are required.

There are no prerequisite local commits: k01 is directly based on the old upstream base. No later kernel commit needs folding into it. Companion v04 `c32113ed68b88457697ed9db1ab24f944ab9c0f4` (batch-invariant residual RMSNorm), v03 `7de1e1c5ec5f3005b0e46bb0ec323f5e5864876c` (GDN scheduling), and v05 `fcab69494f1719e91e416aace17ef6ad501fe900` (KVarN integration) address different numerical/scheduling requirements; deterministic GEMM does not subsume them, and they do not replace GEMM repeatability.

Historical issue #6's saved policy proposal (`benchmark-results/kvarn/perf-ideas-20260908/issue6-body.md:87–93`) suggests using standard deterministic controls and adding effective policy to the custom primitive cache key. That is a future redesign, not an implemented supersession or permission to weaken this release default. `onednn_ext.h:800–809` currently keys dimensions/strides/bias/quantization grouping without a determinism flag. If the parent deliberately introduces a mutable policy later, it must adapt both primitive creation and cache identity, arrange the supported serving opt-in, and test off→on→off. A simple replacement with a runtime flag is insufficient. Keeping the present constant attribute requires no such cache-key change.
