## Requirement and effective released feature

Preserve the Brutus/Arc Pro B70 native Xe2 cache/attention path supporting
the existing RedHat W4A16/BF16-compute model, eager V1 compact K4V2 target
and bundled MTP2 draft, four scheduler slots, long contexts and vision.
Packed history and FP16 transformed resident tails are distinct from model
compute/output dtype. Existing K4V4 and other supported comparison paths
remain supported; this audit does not narrow them to the default profile.

k08 supplies normalized Hadamard transforms, KV scatter, both QKV scatter
lifetime variants, balanced-record packing, native decode with caller-owned
or allocating scratch, independent dequantization and cached-prefill
materialization. The native writer consumes already balanced tensors;
vLLM's Triton code performs Sinkhorn balancing. The mixed reader combines
packed records and resident FP16 pages within one attention/softmax path.

The qualified decoder remains numeric variant **18**, D256/G128, Q24/KV4
and K64 work units. `kvarn_decode_xe2.cpp:15–32` fixes those dimensions and
variant; materialization validates `[slots,128,4,256]` tails and D256/KV4
outputs. Keep the corresponding vLLM factory/admission guards. Native
geometry or window eligibility must not be widened during this release.

The shared `DecodeFwdEpilogue` changes are necessary for the Q6 tile:
coordinate scalar stores/reduction, correct unique LSE row ownership and
zero-denominator handling. `paged_decode_kernel.hpp` writes invalid
natural-LSE sentinels before empty row-local splits can skip the epilogue.
The ordinary `DecodeFwdMainloop` opts out through
`InitializeSplitScratchSentinels = false`; KVarN opts in. Retain these
shared correctness changes with the feature and check ordinary attention.

The final release adds k09's width-aware K4V2 records and k10/k11's reducer
and resident-reader refinements. A replay of only the rolling-main k08
would lose released K4V2 and useful performance behavior.

## Bounded cleanup supported by source evidence

1. Remove definition-only `KVarNFragmentLoader::fill_k_fragment_by_coordinate`
   at `collective/kvarn_decode_mainloop.hpp:383–409`. A whole-repository
   `git grep` at the final released tip finds only that declaration/body;
   the retained variant uses `fill_k_fragment`. This is leftover integer-DPAS
   experiment machinery. **Keep** `load_k_dpas_quantized` and
   `load_v_dpas_quantized`: native materialization calls them at
   `kvarn_decode_xe2.cpp:539/:542`. Recheck callers after replay and run
   the existing independent byte/materializer tests.
2. Correct the stale Xe2 CMake explanation about selectable 128/256-GRF
   variants: only variant 18 is admitted and there is no `grf_size<128>`
   in the attention tree. Retain `MIXED_GRF_SIZE` for this release unless
   measured generated-code evidence proves removal harmless; it also
   affects writer/scatter/materializer helpers without explicit GRF
   properties. The decoder/reducer's explicit 256 properties alone do not
   prove the library-wide flag redundant. Similarly correct comments about
   the removed paired-nibble specialization/ID20 without restructuring
   `KVarNDecodeSharedStorage`: its `base` member preserves storage/barrier
   semantics and is actively used.
3. `legacy_max_logits` is numerically unused: the only internal references
   are its member, null check and assignment; natural LSE uses `exp_sums`.
   Public `max_logits` remains validated, allocated, passed and tracked by
   both repos. Removing that allocation saves `4 * B * 24 * splits` bytes
   per scratch instance, but requires coordinated schemas, callers, guards,
   tests and allocator-lifetime changes. Existing guards inspect named
   fields, not the complete argument list, so deleting the argument alone
   is unsafe. Retain the existing public scratch ABI in the minimum release
   replay; record a coordinated removal as optional follow-up, not assumed
   memory headroom or a release blocker.

The paired v05/v10 cleanups are independently corroborated: the released
`_KVARN_NATIVE_RECORD_BYTES` has only a definition; `_pack_dpas_v4` has
only its wrapper and one shape-error test caller. Preserve the generic
packer and migrate that test. `kvarn_fragment_coords` and `kvarn_dequant`
have real independent GPU-test users, so they are not removable merely
because model serving does not call them. No broad reference-path, format,
native-plan or preset deletion is justified.
