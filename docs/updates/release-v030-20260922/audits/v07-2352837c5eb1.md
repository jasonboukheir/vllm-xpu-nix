## Requirement and effective old behavior

The original KVarN feature rejected bundled MTP whenever
`scheduler.max_num_seqs != 1`. v07 removes that conjunct and the `B1` wording
from `platforms/xpu.py:_check_kvarn_beta_unsupported_config`; it adds admission
cases for 1/4/16 scheduler slots and one/two draft tokens. It changes no
allocator, scheduling algorithm, attention operator or metadata ownership.

The released stack retains this behavior while later commits add compact
K4V2 and supported draft-cache variants. The required Brutus profile remains
the RedHat Qwen W4A16 target, BF16 compute, eager V1, matching K4V2 target and
bundled MTP2 caches, TP1/PP1, four slots, 2,048 prefill tokens, bounded image
inputs and disabled prefix caching. The 16-slot unit case only checks
admission policy; it is not evidence that sixteen full-context requests fit.

## Exact-target upstream coverage

`git grep -i kvarn ced6857... -- vllm tests` finds no implementation. The full
old-base-to-v0.30 diff for `vllm/platforms/xpu.py` changes only
`IrOpPriorityConfig.with_default(..., gelu_and_mul_sparse=["native"])`.
It neither supplies nor replaces the KVarN admission guard.

The existing TurboQuant route at target `platforms/xpu.py:151–153` is not an
equivalent cache: `turboquant_attn.py:customize_spec` calculates packed
per-token slot sizes and does not provide KVarN's tile/tail/flush contract.
Replacing KVarN with that route would not preserve the requested behavior.

The generic target scheduler already owns concurrent admission:
`v1/core/sched/scheduler.py:124` assigns `max_num_running_reqs` directly from
`scheduler_config.max_num_seqs`. Its waiting loop at lines 860–865 counts
running requests plus paused streaming requests that still hold runner slots
and stops at this limit. No KVarN-specific scheduler is necessary.

Unlike the earlier issue-17 snapshot, **this target has no
`max_num_active_seqs` field**. Do not introduce it or port the prior report's
active-cap recommendation. `max_num_seqs` remains the capacity/reservation
dimension for this release.
