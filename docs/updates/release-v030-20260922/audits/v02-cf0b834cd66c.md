## Requirement and effective released behavior

Native GDN enforces exact request-metadata extents even when data buffers have padding. The adapter must distinguish request count, token count, and speculative rollback-column capacity. The original patch adds only 22 lines, including its comment, to `vllm/_xpu_ops.py`:

| Input | Extent passed to native GDN |
| --- | --- |
| `non_spec_query_start_loc` | `num_prefills + num_decodes + 1` |
| `non_spec_state_indices_tensor` | `num_prefills + num_decodes` |
| `spec_query_start_loc` | `num_spec_decodes + 1` |
| `spec_state_indices_tensor` | `num_spec_decodes` rows, all columns retained |
| `num_accepted_tokens` | `num_spec_decodes` |

These are local tensor views. `None`, metadata ownership, padded backing storage, token-index arrays and projected/output buffers remain unchanged. Exact-size eager inputs preserve their values and storage. The pre-existing non-spec `.contiguous()` call is not introduced by v02.

All five slices survive unchanged at released tip `2fdd9d71`; `git diff cf0b834c..2fdd9d71 -- vllm/_xpu_ops.py` shows only v03's additional mixed-batch counts/predicate/native keyword. No later local commit reverts or supersedes v02. The relevant workload is native Qwen GDN on XPU, including Brutus's retained MTP configuration. K4V2 attention compression does not remove GDN recurrent state. Eager qualification alone does not retire this already-shipped boundary contract.

## Revalidated upstream coverage

All vLLM line references below are at `ced6857a`; all native references are at `1c7cbeee`.

2. **The existing upstream partial fix predates our old base.** `cec2ec11760f9f3beabd4c90451936078bf91533` (#45100) replaced graph metadata `batch_size = m.num_actual_tokens` with `m.num_reqs`. An ancestry check confirms it is already in `51da0ca6`. It fixes token/request confusion, but does not normalize padded request counts to live group counts.
3. **Request padding remains a producer/consumer mismatch.** `GDNAttentionMetadataBuilder.build`, `gdn_attn.py:263–315`, excludes zero-length request padding from speculative/non-spec live groups. Its graph branch, lines 424–473, expands speculative state/query/acceptance arrays to `m.num_reqs`; non-spec graph arrays are handled at 475–494. V1 itself can pass padded request metadata: `GPUModelRunner._build_attention_metadata`, `gpu_model_runner.py:2297–2323,2458–2465`, builds common metadata using `num_reqs_padded` and `num_tokens_padded`. Thus this evidence is not specific to issue #17's V2 work. Current eager production avoids graph padding; the fix remains a harmless view normalization on its exact-size inputs.
4. **Concrete source-derived residual:** two live speculative requests plus two suffix padding rows can yield `num_spec_decodes == 2` with graph state/query/accepted extents `4/5/4`. Native requires `2/3/2`. These native predicates, not a claimed GPU reproduction, demonstrate why the unpatched boundary rejects this metadata. This repair assumes padding follows live rows; it is not a general filter for interior zero-length requests or a fix for incorrect scalar counts.
5. **Native consumers remain exact-sized.** `csrc/xpu/gdn_attn/gdn_attn_interface.cpp` is byte-identical between old kernel base and v0.1.15: blob `a05bcfa1b8aad28ad1950553ba954c40aa000610`. `causal_conv1d_spec` requires exact query length at lines 68–70, state-row count at 92–95, and accepted-count length at 115–117. `causal_conv1d_non_spec` enforces query/state sizes at 292–295 and 321–324. Legacy `gdn_attention`, lines 766–904, forwards these arrays into the split operators without trimming. Separate data buffers use `>= num_actual_tokens` checks; replacing their extents is neither needed nor justified by v02.
6. **Actual upstream changes do not cover this requirement.** The sole old-base-to-v0.30 Qwen GDN model change is `f6326f53bda46898a331c2d24500332c285d9a2b` (#55715), enabling FlashInfer prefill on CUDA SM12x. It does not change XPU dispatch or request metadata. No old-base-to-selected-kernel change touches the native interface above. In particular, the issue #17 snapshot's `da16a559` ragged rollback improvement must not be assumed present: selected v0.1.15 still has the strict `spec_token == num_spec_decodes * (num_speculative_tokens + 1)` assertion at line 119. That is a separate k06 audit/replay obligation.

## Minimum residual, pairing and folds

Replace the long comment with the narrow verified statement that request-index arrays must match native scalar request counts while token buffers retain their existing extent.
