## Disposition and minimum residual

**KEEP**, folded into the one coherent v05 KVarN feature. Retain the original
narrow 11-line V1 exclusion and the five ownership regression cases. The
original ownership logic itself needs no target-specific rewrite; any
surrounding v05 integration adjustments must preserve its behavior.

Do not broaden the exclusion to ordinary attention backends, remove draft
names from `KVCacheGroupSpec.layer_names`, or reconstruct first-pass MTP
metadata through a new code path. Allocation and binding still use the full
physical groups (`initialize_kv_cache_tensors` at line 7344), independently
of mutable metadata ownership.

Two existing integration obligations deserve focused checks while folding
v05; they are not a request to port V2 or DFlash:

1. **Physical zeroing must see draft storage.** V1 `_init_kv_zero_meta`
   passes `_kv_cache_spec_attn_group_iterator()` to `KVBlockZeroer`; that
   iterator at line 7338 enumerates only target `self.attn_groups`.
   `KVBlockZeroer` enumerates only each supplied group's `layer_names`.
   Consequently, the v11 exclusion also removes draft names from this
   physical enumeration in the old released stack. Some packed layouts may
   incidentally span another layer's bytes, but source inspection does not
   establish coverage for independent draft allocations. Include applicable
   draft groups in the **physical zeroing** input, without creating a second
   metadata builder or restoring target ownership. Assert draft-only and
   shared-group coverage, null-block initialization and pool-qualified
   zeroing. Keep physical group IDs/counts paired. Similarly check resolved
   block sizes for a draft-only group: `prepare_kernel_block_sizes` receives
   target groups before draft builders exist. This release uses the existing
   fixed KVarN block geometry, not newly supported split geometries.
2. **Lifecycle reset has two boundaries.** Released
   `gpu_worker.py:513` performs whole-model `reset_process_state` before
   `load_model`, which must remain before both target and draft construction,
   never between them. At v0.30.0, runner `shutdown` calls
   `_cleanup_profiling_kv_cache` (lines 6569/6593). It clears runner groups,
   layer cache references and generic scale views; it knows nothing about
   KVarN's retained `_kv_cache_ref`, tail pools, global registry or builder
   shadows. Confirm prompt shutdown reclamation and any supported retained-
   model cache replacement. If such replacement is reachable, invalidate
   cache bindings and owner shadows while preserving live implementation
   registration; blindly calling whole-model reset would erase `_all_impls`.
   Graph profiling stays guarded. This audit does not claim a runtime leak
   was reproduced or require enabling a new reinitialization mode.
