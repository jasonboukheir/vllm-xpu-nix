**Requirement and surviving implementation.** On native Xe2 Qwen GDN, cached one-token decode output and recurrent updates must remain unchanged when an unrelated fresh prefill shares its call. The regression uses BF16 inputs, FP32 SSM state, K16/V48 heads, D128, width four, TP1, a 127-token prefill and distinct cache slots 3/1. Historical hardware was Arc Pro B70. This concerns convolution/SSM state independently of attention-cache quantization.

k05 adds trailing `split_mixed_non_spec=False` to `_xpu_C.gdn_attention`, its declaration and implementation. For opted-in Xe2 calls it slices decode-first inputs/output/z and request metadata, rebases prefill query offsets, and runs existing convolution→delta stages separately. Both intermediate sets remain alive until all kernels are enqueued. Native guards require both groups, no speculative decodes or token indirection, and required metadata. The paired Python guard supplies one-token decode and exact token-total invariants. Default-false and non-Xe2 dispatch retain their original behavior.

Through the final released tip, k05's schema, split and test are unchanged. The sole later interface difference is k06's speculative-capacity assertion; no later repair/revert supersedes k05.
