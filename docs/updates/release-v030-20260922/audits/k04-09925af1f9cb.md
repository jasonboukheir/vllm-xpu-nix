# k04 — preserve fresh-state O2 ordering; qualify the smaller barrier change

**ADAPT, with GPU qualification pending.** The minimum residual remains one
`sycl::group_barrier(item.get_group())` inside `if (!has_prev_state)`, immediately
before the output `dv` loop in `chunk_fwd_o_kernel`. Preserve existing upstream
barriers. Removing k04's U-barrier substitution and unconditional per-chunk
barrier is justified by source analysis, but is **not a qualified replacement**
until the comparisons below pass. If they fail, retain the released protection

At the frozen header, `global_fwd_o(batch_size,num_v_heads,1)` (line 1471)
assigns one request/value-head per work-group, with eight subgroups and serial
chunk/dv loops. O2 is stored at line 1087 and consumed at 1163 or 1223:

- Stateful O2 and current-dv U already cross the group barrier at 1160.
- S stores at 1210 precede the next chunk's barrier at 985 and its later S reads.
  The unconditional added barrier duplicates this ordering.
- Fresh-state work-groups skip the stateful branch and reach the O2 read at
  1223 without a barrier after O2 stores. S computation does not synchronize
  these subgroup producers/consumers. `has_prev_state` is work-group uniform,
  making the proposed conditional barrier valid.

Earlier upstream `c9989668e7f280747680def85d58d116126c2249` (#411) added the
next-iteration SLM barrier; `619c409849500e0f56f8da00d5f11c4aa75cd6f9` (#560)
changed local-only fences to group barriers. The
[SYCL reference](https://github.khronos.org/SYCL_Reference/iface/group-functions.html#sycl-group-barrier)
specifies release/acquire memory ordering across the group: U's existing barrier
already covers global writes. A compiler defect would require separate evidence.

(interface line 696). Upstream `f6326f53bda46898a331c2d24500332c285d9a2b` enables
