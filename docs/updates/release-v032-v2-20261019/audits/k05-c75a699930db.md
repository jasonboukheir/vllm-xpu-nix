## Requirement and surviving behavior

The native GDN speculative query length and its allocated rollback capacity
are different quantities. A shortened or ragged verification must consume the
previous accepted state even when that acceptance exceeds this step's query
length, visit only live token indices, preserve unused state/output storage,
and leave correct history for the next verification.

The assigned commit changes only
`tests/gdn_attn/test_gdn_attn_padded.py`, adding
`test_gdn_shortened_mtp_preserves_rollback`. Its 24 parameter combinations
exercise current lengths `(2,)`, `(1,)`, `(3,2,1)` at capacity three, previous
acceptance one or three, both input layouts, and head geometries `(4,8,32)`
and `(16,48,128)`. Inputs are BF16 and SSM storage is FP32. Three interleaved
convolution layers guard the selected layer's physical stride and its adjacent
layers. Sparse global token indices and extra output rows guard unscheduled
positions. Active outputs and states must match full-width execution exactly;
subsequent full-width execution compares every possible accepted prefix.

Neither later kernel commit changes this test. These requirements apply to
the Qwen target's recurrent layers even when its attention KV uses KVarN and
the external DFlash2 model uses BF16 sliding-window attention. They do not
depend on how the draft model itself stores attention KV.
