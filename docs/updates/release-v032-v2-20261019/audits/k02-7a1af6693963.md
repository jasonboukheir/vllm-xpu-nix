## Requirement and effective behavior

Fresh GDN prefills must produce correct, repeatable projected Q/K/V regardless
of stale contents in a recycled convolution state slot. The retained historical
record describes corrupted Q/K/V and repeated `!` output on Arc Pro B70 for
prefills of at least eight tokens with oneAPI 2026.0. A metadata-recomputation
experiment did not eliminate the problem. These are recorded observations;
they do not establish a compiler root cause.

k02 adds a constant false guard in
`csrc/xpu/gdn_attn/gdn_attn_interface.cpp::causal_conv1d_non_spec`. In the XE2
prefill branch it always selects `gdn::chunk_causal_conv1d_xe2` with fused L2
normalization instead of the SLM-tiled implementation. Decode-only and
non-XE2 routes remain unchanged. The production change is nine added lines
and one replaced line, accompanied by a focused 100-line regression.

`tests/gdn_attn/test_causal_conv1d_replay.py::test_qwen38_fresh_prefill_replay_is_exact`
uses the production geometry, 162 tokens, fresh-state metadata, and recycled
state fills 0, 3.25 and -1.75. It compares every returned intermediate, z and
the selected final convolution state exactly over repeated calls. This catches
replay instability and dirty-state dependence; stable incorrect output still
requires an independent numerical oracle.

No later commit supersedes the guard or changes the test. k04 adds a mixed
batch split, but its prefill subgroup calls this same guarded function.
