## Requirement and actual implementation

k08 supplies native K4V4; k09 makes two-bit values readable and writable
through that same Xe2 feature. Brutus/B70 needs this for the retained D256
target and bundled MTP. D256/G128 records shrink from 35,072 to **26,880
bytes per block/head**: unchanged 16,384-byte keys and 2,304-byte metadata,
with values reduced from 16,384 to 8,192 bytes. This saves 23.36% of packed
attention storage, not total VRAM. Model BF16 compute, rotated FP16 resident
tails and packed K4V2 storage are separate contracts.

The substantive delta is coherent across five native operators:

- `kvarn_pack_balanced_kv_xe2` in
  `csrc/xpu/attn/xe_2/kvarn_balanced_writer_xe2.cpp` templates value width.
  `KVarNBalancedWriterKernel<2>::write_value_pair` assigns tokens `t,t+2`
  to one workgroup because their DPAS fields share bytes. Each byte has
  exactly one writer; independent per-token range/scale and ties-to-even
  rounding remain essential. Caller-provided balanced tensors and unique
  block IDs remain prerequisites.
- `KVarNFragmentLoader<DpasPacked,ValueBits>` in
  `collective/kvarn_decode_mainloop.hpp` parameterizes natural row sizes,
  DPAS lane widths, masks and V prefetch extents. Width-dependent metadata
  follows the V payload; physical tensor strides remain authoritative.
- `kvarn_decode_with_scratch_xe2` selects
  `KVarNDecodeD256G128DpasQ6PrefetchRecordCursorConfig<2>` or `<4>`;
  `kvarn_decode_xe2` forwards the width through its allocating wrapper.
  Decode still requires DPAS layout and variant 18.
- `kvarn_dequant_xe2` and `kvarn_materialize_packed_kv_xe2` reconstruct both
  natural and DPAS records with matching offsets. Materialization also
  follows request block tables and resident-tail indirection; it is not
  interchangeable with a contiguous bulk dequantizer.

`csrc/flash_attn/flash_api.cpp` appends `value_bits=4` to all five schemas.
Existing K4V4 callers retain their dispatcher defaults; K4V2 callers must
explicitly pass 2. Record-width checks cannot infer format from padded
storage alone. The paired layout flag and width must agree at every writer
and reader.

k09 additionally prefetches the next resident FP16 page into L2 for K4V2,
bounded by the current split and sequence extent; K4V4 retains its existing
path. This supports the paired eight-block recent-FP16 policy without
changing attention arithmetic. That residency policy is not a sliding mask.

## D128 coverage and limits

Generic D128 support is real source coverage, but not k09 native coverage.
Released `KVarNConfig` computes a **13,824-byte D128/G128/K4V2 natural
record**; `_sinkhorn_pack_kv`, the generic materializer and Triton fused
decode parameterize D, head ratio and value width. The backend advertises
D128; its per-token verify plan represents noncausal queries with full
sequence lengths and disables the internally causal uniform-query path.

Actual barriers remain: compact XPU defaults select D256 DPAS, and
`validate_kvarn_native_factory_selection` rejects natural layout with the
default variant 18. Native writer/materializer geometry remains D256/KV4;
decode adds Q24 and zero-window admission. Simply overriding layout does
not create a working D128 compact profile.

Generic `_kvarn_fused_decode_kernel` masks a suffix beginning at
`seq_len-SLIDING_WINDOW`; that is reusable single-query machinery, not proof
of syvai's multi-query noncausal window semantics or bounded allocation.
`KVarNAttentionBackend` inherits `supports_sliding_window=False`, XPU config
skips sliding layers, and `_flash_attn_varlen` forwards causality without a
window argument. Thus D128/Q32/KV8/window2048 needs deliberate dispatch,
mask/allocation and context-insertion work. Existing tests reviewed here
do not qualify that combined contract. Preserve D256 target/MTP and vision
while adding it; never reinterpret D256 records.

## Validation

Observed: immutable diff/caller/history inspection, patch-ID verification,
and a host arithmetic enumeration of k09's V mapping: all **32,768 logical
values** match reader byte/field coordinates, with **8,192 unique byte
writers** covering offsets 0–8191. This is not compiled-kernel execution.
No pytest, native build or GPU tests ran.

Historical commit evidence records 132 packing/decode GPU cases and 24
paired causal/reject cases; `xpu-v1.9.0.md` records 603 final installed checks
and later block-load benefits. `xpu-v1.10.0.md` records all-K4V2 MTP/vision
qualification, alongside retained semantic and NaN-poisoning failures.
These do not establish new-snapshot results or isolate k09 performance.
