## Requirement and effective final-old-stack behavior

On Xe2, an ordinary cached one-token Qwen GDN decode changes arithmetic when
an unrelated prefill joins its batch: `gated_delta_rule_non_spec` selects the
Xe2 chunk implementation whenever any prefill exists, including for the decode
row. This fix preserves each eligible request's standalone arithmetic by
splitting the fused call into decode and prefill groups. It does not claim
whole-model determinism.

The focused regression uses BF16 inputs, FP32 recurrent state, 16 key heads,
48 value heads, head dimension 128, convolution width four, TP1, a 127-token
fresh prefill and separate state slots 3/1. Historical hardware was Arc Pro
B70. The retained property is independent of KVarN KV quantization, RAM prefix
residency or the draft model's BF16 sliding cache.

The native implementation narrows contiguous decode-first input, output and z
tensors, slices request/state metadata, rebases prefill query offsets, and calls
the existing convolution and delta stages separately. Decode receives zero
prefills and therefore uses `gdn::gated_delta_rule`; prefill retains
`chunk_gated_delta_rule_xe2`. Both intermediate tensor vectors remain alive
until the complete mixed launch chain has been enqueued. It adds orchestration,
not a separate mathematical implementation.

Native guards require both groups, zero speculative decodes, no token indexing,
and present query-start/state-index/initial-state metadata. The paired Python
predicate additionally requires one token per decode, exact ordinary token
totals and no speculative masks. The implementation relies on that caller's
decode-first metadata contract; it does not independently validate every
query length. The split body is compiled only with `VLLM_XPU_ENABLE_XE2`.
The trailing `split_mixed_non_spec=False` schema argument preserves old callers.

Function comparison confirms the fused `gdn_attention` implementation and AST
comparison confirms its focused test are unchanged between the assigned commit
and the final old kernel tip. Later k05/k06 tests and k07 KVarN operators do
not supersede or repair this behavior. No later local repair needs folding into
this commit.

The kernel upstream delta is empty by release selection, not merely patch-ID
similarity. vLLM's exact 0.32 dependency remains kernel wheel 0.1.15.4.
Alternate vLLM implementations and relevant upstream changes were inspected:

- `e4294144a8ca4e57da712934dca33f89bef8fe78` (#59735), titled
  “Keep non-speculative GDN decode on the standard path”, replaces generic
  fused CUDA dispatch with `enable_fused_gdn_spec_decode`. The gate requires
  `gdn_decode_kernel == "cuda"`; XPU chooses `"XPU"` and its separate unchanged
  `forward_xpu`. This similarly named improvement does not cover k04.
- `0eac15270710ddb7f5296d7244fcd0496c2daa0f` (#56531) retains rows with
  `num_decode_draft_tokens_cpu >= 0` on the speculative path even when all
  draft counts are zero. The accepted-token recurrent-state offset still
  matters. Preserve target `gdn_attn.py:287–304`; do not infer an ordinary
  decode from a one-token query or zero draft sum.
- Target `gdn_attn.py:306–343` treats a fresh one-token first chunk as prefill,
  including `is_prefilling`/prior-state checks, while excluding trailing
  padding. A cached one-token decode beside such a fresh request is a useful
  mixed-split regression, not a reason to revert classification.
- Target `gdn_attn.py:371–379` reclassifies non-spec decodes as prefills when
  speculative rows coexist, leaving the ordinary native split disabled.
  This is required for indexed speculative grouping and rollback semantics.

V2/DFlash2 therefore changes which batches are eligible, but does not retire
the ordinary arithmetic requirement. Its target GDN verification rows retain
their own speculative path even though the external drafter uses BF16 sliding
attention. Four-request joins/leaves and restored recurrent state need runtime
qualification; KVarN compression and full 262K context are separate concerns.
