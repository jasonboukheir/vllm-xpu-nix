## Requirement and final-old behavior

For native Xe2 Qwen GDN, a cached one-token decode must preserve its output and recurrent-state update when an unrelated fresh prefill shares the call. The regression uses BF16 inputs, FP32 SSM state, 16 key heads, 48 value heads, D128, convolution width 4, TP1, a 127-token prefill and nonconsecutive cache slots 3/1. Historical preflight identifies Intel Arc Pro B70. The requirement concerns recurrent convolution/SSM state independently of KVarN attention-cache format.

k05 adds `split_mixed_non_spec=False` to `_xpu_C.gdn_attention`, its C++ declaration and implementation. Under `VLLM_XPU_ENABLE_XE2`, an opted-in call slices contiguous decode-first tokens, output/z views and request metadata; rebases prefill query offsets; then runs existing `causal_conv1d_non_spec` → `gated_delta_rule_non_spec` separately for decode and prefill. Both intermediate sets remain alive until all kernels are enqueued. This preserves ordinary decode arithmetic without replacing numerical kernels.

Native checks require both groups, no speculative decodes, no non-spec token indirection and required metadata. The paired caller supplies the stronger one-token-per-decode/complete-token-total contract. The flag defaults false, and non-Xe2 execution retains its original path. It is not a general speculative-mixed or arbitrary-token-layout split.

There is no subsequent local repair/revert to fold into k05. Through the released kernel tip, the mixed implementation and regression remain unchanged; the interface's only later change is k06's speculative capacity check. The v03 caller is also unchanged through released vLLM. Thus k05 has an effective contribution in the final old stack.
