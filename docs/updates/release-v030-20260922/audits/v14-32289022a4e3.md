## Requirement and retained behavior

Two long requests can fit compressed storage while their combined history
exceeds the shared FP16 materialization scratch. Before v14,
`KVarNAttentionImpl._materialize_cached_prefill_kv` raised `ValueError`, then
`_cached_multiquery_path` selected the incompatible natural-layout slow reader,
which correctly rejected DPAS records. Retain this fix for Arc Pro B70,
RedHat Qwen3.8-27B W4A16/BF16, eager V1 K4V2 target/draft MTP2, four scheduler
slots and vision, together with previously supported formats. Neither later
commit changes v14's backend or its two modified test files at released tip
`2fdd9d71f6895379b0940a8f755b4c9095840558`.

At that tip, `vllm/v1/attention/backends/kvarn_attn.py:5222`
`_cached_multiquery_overflow` reuses scratch serially only for DPAS batches
with multiple requests, aggregate overflow, and every positive sequence length
within both scratch capacity and `md.max_seq_len`. Single-request overflow
remains unsupported. It validates live query boundaries, skips empty query
spans, selects the corresponding physical block-table row and slot slice,
rebases offsets to zero, clears stale batched FA/virtual-row plans, and copies
each result into its original output range. Preserve these eligibility checks:
catching `ValueError` alone does not prove aggregate overflow.

Retain normal fitting-batch/native-verify dispatch, packed/resident reconstruction,
Hadamard transforms, GQA, scaling and bottom-right causal alignment; metadata
replacement also preserves `causal=False`. This establishes intended attention
semantics, not bitwise equivalence between differently shaped launches.
Scratch remains shared by `(device, D, Hkv)` with row count
`max(min(max_num_seqs * max_model_len, 262144), max_model_len, 4096)`.
Do not enlarge it per request or describe 262,144 as a universal hard cap.

## Actual release-target alternatives and adaptation

Both targets have no KVarN implementation. Target
`TurboQuantAttentionImpl._prefill_attention` processes continuations per request, uses
virtual decode rows for small queries, and calls `_continuation_prefill` with
WorkspaceManager-backed dequantization for larger ones. Its per-token
centroid/SoA or AoS representation cannot read KVarN group records, Sinkhorn
metadata, DPAS packing or resident pools. Its backend blob is unchanged from
the old base: `8542e6164f0303a618194b45f4b7efd054a5a0a1`.
This is a useful alternative design, not replacement coverage.

Kernel target `csrc/flash_attn/flash_api.cpp:varlen_fwd` accepts FP16/BF16/FP8
Q/K/V, without KVarN reconstruction. Included upstream
`0b647c5717a382c6d7ea645571d3dbe8c7640696` generalizes paged block-size
dispatch using b16 policies; it does not solve compressed-history overflow.

Included vLLM commit `5fe77aecfc7687c1f3cc49862022ce34d45d1784` removes
`CommonAttentionMetadata`'s deprecated exact CPU lengths and proposer shadow
maintenance. Target `GPUModelRunner._prepare_inputs` constructs optimistic CPU
lengths assuming all drafts were accepted; `_build_attention_metadata` passes
them as `seq_lens_cpu_upper_bound`. Its explicit contract forbids using that
bound as exact async-spec history.

The minimum adaptation is to preserve KVarN's local exact list from live
`seq_lens` for active request rows, or a correctly invalidated scoped exact
shadow. The released builder already falls back to `cam.seq_lens.tolist()`
when the removed property is absent. Reuse that exact list in materialization
and overflow; keep cumulative K offsets, max length and device lengths
consistent after rejection, draft advancement and reordering. Never substitute
the optimistic bound. Coordinate with v11/v16's ownership and advancement
repairs; measure any additional host synchronization without weakening exactness.

No separate repair commit or new kernel ABI is needed. v10
`80d5166fcb0b7935f3f95b8d343e3e669940261f` supplies compact widths;
k08 `9bb1e2d428b8a25b262c0cd6704614bdf6ee3ad8` and k09
`f26ef2323399ab410299db5c8caec41c8d63215a` must retain the paired
`_vllm_fa2_C.kvarn_materialize_packed_kv` operator and trailing `value_bits`.
Keep native and Triton reconstruction paths.

Native `kvarn_decode_xe2.cpp:kvarn_materialize_packed_kv_xe2` and ordinary
FA through `csrc/utils.h:vllmGetQueue` use the current XPU stream. Serial
materialize/consume/copy/overwrite ordering and persistent buffer ownership
are essential. Geometry-keyed shared scratch has no cross-stream ownership
protocol. Retain eager execution; host reads and dynamic loops do not establish
graph safety or concurrent-stream safety.

## Evidence and remaining qualification

Observed: immutable patch/parent/hash verification, empty v14-to-released-tip
diff for all three affected files, target negative searches, alternative
call-path/blob comparison, upstream metadata-removal inspection and paired
schema/queue inspection. No runtime tests were executed in this audit.
[xpu-v1.9.0](../../../releases/xpu-v1.9.0.md) records before/after reproduction,
twelve bounded-scratch CPU cases within 603 installed tests, GPU attention/
canary/reuse checks and at least 302,976 simultaneously occupied attention
tokens. These are historical evidence, not qualification of the new pair.

Retain the twelve CPU cases covering fitting/overflowing ragged batches,
causal/noncausal masks and present/missing exact CPU lengths. Retain the XPU
fixture's independent SDPA oracle, capacities 385/260, both value widths,
packed/resident pages, unchanged cache, canaries and repeated scratch reuse.
Its `num_decodes=2` and padded record stride disqualify native materialization;
it tests Triton reconstruction and does not forbid ordinary FA fallback.

Pending after replay: native-eligible continuation overflow with asserted
dispatch and direct FA-fallback rejection; nondefault-current-stream reuse;
invalid extents/zero-query boundaries; deliberately optimistic CPU bounds with
exact live lengths; MTP rejection/reordering and target/draft ownership;
concurrent long requests with bounded memory, retained vision, and matched
old/new V1 performance. Upstream alone cannot run the KVarN regression; compare
the complete adapted feature with/without this fallback to isolate its benefit.
