## Requirement and actual final behavior

The patch turns `kvarn_k4v2_g128_compact` into a supported uint8/quant-mode
105 storage and native attention path. For D256/G128 a record contains
16,384 bytes of four-bit keys, 8,192 bytes of two-bit values and 2,304 bytes
of scale/zero-point metadata: **26,880 bytes per block/head**, versus 35,072
for K4V4. The value width reaches the Python DPAS packer, native writer,
decode and both native/Triton materializers. Compute dtype and resident FP16
tails remain separate from packed storage.

The final released `kvarn_attn.py:KVarNMetadataBuilder._lifecycle_policy`
keeps eight recent full blocks when flushing at sixteen, within the existing
sixteen-block prefill reservation. K4V4 retains its 4/0 policy. This is a
history quantization policy, not sliding-window attention. Its final selection
comes from each physical group's `kv_cache_spec.kv_quant_mode`, not the target
configuration globally.

The final `triton_kvarn_decode.py:_kvarn_native_split_count_cached` retains
sixteen splits for precisely three K4V2 rows and inclusive context extents
4096–8192; MTP2 virtual rows are included. Other batch/context choices and
32-split scratch reservation stay unchanged. The packed-KV Triton kernel's
grid is `(pages, requests, heads)`, keeping page count out of constexpr
specialization. These are useful existing behaviors, not new release gains.
