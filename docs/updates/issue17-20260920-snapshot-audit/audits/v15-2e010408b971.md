The requirement is explicit BF16 draft-cache admission for existing bundled
Qwen MTP with a compact K4V2 target, plus meaningful correctness references.
The historical B70 profile uses W4A16 weights, BF16 compute, eager V1,
TP1/PP1, one/two speculative tokens and at most 2,048 batched prefill tokens.
At the parent, `_check_kvarn_beta_unsupported_config` rejects `bfloat16`
draft storage. v15 adds only that admission branch and diagnostic wording to
production code. It does not implement allocation, attention, backend
isolation, or dtype conversion. K4V4-target/BF16-draft and `auto`/`bf16`
aliases remain rejected. Other guards and target precision remain intact.
The five touched files have an empty diff between v15 and final release;
v16's independent CPU-shadow repair does not supersede this patch.

**Minimum residual:** retain the exact legacy admission capability and CPU
contract tests within the KVarN feature, without advertising newly qualified
V2 BF16 serving. Issue17 retires a BF16 serving milestone, not this existing
explicit option or small reference calculations. Do not broaden admission,
change defaults, introduce silent fallback, or schedule a BF16 model-serving
arm. The required integration proceeds directly to K4V2 for both caches.
Preserve matching/mixed-format MTP behavior while adapting the platform's V2
capability checks to actual implemented paths.

Upstream does not supply KVarN or this admission rule. Useful generic behavior
already predates old base `51da0ca66c8065619c79e35dff97aa99aeaf5644`:
`fd74c90d9c3b5c35308f1f0ab308469235fa5277` independently selects the V1

`8bfd6839016f9670508cf07c16c68891f83ea117` applies the draft cache dtype
through dataclass replacement. Both remain present at the target. Reuse
them; v15's three-format test verifies target configuration stays unchanged,
draft dtype survives, and XPU chooses FlashAttention for BF16 versus KVarN
for compact storage. This is regression coverage, not missing production
implementation to duplicate. The old-to-new XPU changes are docstrings and
sparse-GELU dispatch, not admission coverage.

The BF16 `(target_bits,draft_bits)=(2,16)` test additions exercise v12's whole
compatible groups and v13's recurrent reservations with an ordinary
`FullAttentionSpec`. They assert group sizes `[1,16,48]`, unchanged estimated
capacity/bytes versus previous grouping, and adequate recurrent slots under
attention-capacity overrides. They add no allocator or schema. Retain these
cheap heterogeneous-spec controls alongside compressed-format cases. Their
synthetic specifications do not establish physical pointer separation,
runtime ownership, or V2 lifecycle correctness.

V2 makes the isolation test's scope especially important.
`gpu/spec_decode/eagle/utils.py:load_eagle_model` overrides cache dtype but
changes the attention backend only when explicitly supplied; it can inherit
the target backend. `DraftModelSpeculator.attn_vllm_config` returns target
configuration, although `set_attn` filters to draft layers.
`gpu/model_runner.py` still initializes target builders without the matching
active-layer exclusion; autoregressive `propose` passes target metadata into
draft prefill. The existing V1 test proves none of those paths. Extend CPU
coverage to the actual V2 loaders/builders, preserve exclusive mutable KVarN
ownership, and ensure the dedicated draft owner builds prefill metadata.
Do not apply an unconditional filter that breaks ordinary metadata reuse or
hidden-state extraction. DFlash has separate insertion order, D128 geometry,
and window semantics; this patch supplies none of those requirements.

**Independently useful tests:** preserve
`test_bf16_draft_paged_attention_matches_independent_causal_reference` in
`tests/v1/attention/test_xpu_unquantized_cache.py`, preferably with the
independent native-dtype fix. Its twelve cells cover batches 1/4, query lengths
1/3/129, D256 Q24/KV4, permuted physical pages, and zero/123 padding.
FP32 SDPA with an explicit bottom-right causal mask supplies expected output;
the test also poisons the final visible value, requires earlier queries to
remain identical, restores it, and checks exact replay. This covers causal
visibility and overwrite/restore, not full scheduler rejection or rollback.
Lengths 257–641 do not establish long-context split-K behavior, D128, or
noncausal sliding windows.

contract. Ordinary upstream attention tests are not a replacement for these
XPU D256/GQA cells. No new native ABI is needed.
