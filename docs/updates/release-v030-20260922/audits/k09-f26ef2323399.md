## Requirement and implementation

k08 supplies native K4V4; k09 extends that feature to two-bit values. A
D256/G128 record contains 16,384 key bytes, 8,192 value bytes and 2,304
metadata bytes: **26,880 bytes/block/head**, versus K4V4's 35,072. This saves
23.36% of packed attention storage. BF16 model compute and rotated resident
FP16 tails remain separate contracts.

At k09, `csrc/xpu/attn/xe_2/kvarn_balanced_writer_xe2.cpp` templates
`KVarNBalancedWriterKernel<ValueBits>`. `write_value_pair` owns tokens
`t,t+2` together because their DPAS fields share bytes, preventing competing
writes. It retains independent per-token ranges/scales, ties-to-even rounding,
metadata placement and zeroed trailing padding. The writer requires DPAS,
D256/G128/KV4 and caller-proven unique block IDs.

`collective/kvarn_decode_mainloop.hpp:KVarNFragmentLoader` parameterizes value
row/DPAS-lane widths, masks, metadata offsets and prefetch extents. Native
decode selects `<2>`/`<4>` versions of
`KVarNDecodeD256G128DpasQ6PrefetchRecordCursorConfig`; it still requires Q24,
KV4, DPAS and variant 18. `kvarn_dequant_xe2.cpp` and
`kvarn_decode_xe2.cpp:kvarn_materialize_packed_kv_xe2` reconstruct natural or
DPAS records using physical strides. The latter also resolves request block
tables and resident-tail slots, which contiguous dequantization cannot replace.

The K4V2-only next-resident-page L2 prefetch is bounded by split and sequence
extent. It complements the paired recent-FP16 history policy without changing
attention arithmetic or introducing a sliding-window mask.

## Disposition, ABI and folds

**KEEP the substantive implementation/tests and fold into owning k08**
`9bb1e2d428b8a25b262c0cd6704614bdf6ee3ad8`. No demonstrated upstream
coverage permits dropping this storage or performance feature. Preserve
existing guards, K4V4/default-width compatibility and reference readers;
no new native geometry or window contract is needed for this release.

Pair with v10 `80d5166fcb0b7935f3f95b8d343e3e669940261f`, folded into v05.
`flash_api.cpp` appends `value_bits=4` to writer, dequant, materializer,
allocating decode and scratch decode schemas. Released vLLM's
`kvarn_native_value_bits_kwargs` explicitly passes 2 for K4V2;
`kvarn_native_layout_abi_supported` and `kvarn_native_decode_abi_supported`
verify schema arguments before dispatch. Physical padding cannot identify
the format, so width/layout agreement must survive every caller and reader.

Retain final vLLM ownership, group-local 16/8 history and bounded-materializer
repairs identified by v10; they are prerequisites for target/draft correctness.
k10 `c69cfad0586bb0eda4218fae495f446ae0e845bc` replaces only the sixteen-split
fused output/Hadamard reducer with a 64-thread/four-column implementation.
k11 `2c39287deec5e59cc2656e6d4a6dce51a567c411` adds K4V2 resident block loads,
with independent K/V 64-byte-alignment checks and scalar fallback. Neither
changes this packed ABI. Fold their audited final behavior into k08, retaining
their separate correctness/performance gates rather than attributing gains to
k09 alone.
