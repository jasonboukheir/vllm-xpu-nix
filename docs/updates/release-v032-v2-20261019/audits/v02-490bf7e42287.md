## Requirement and effective old behavior

Native Xe2 Qwen GDN changes arithmetic when a prefill is split at a different
token boundary, or when a cached one-token decode joins a prefill and is routed
through the chunked prefill implementation. This commit preserves two narrow
properties independently of attention-cache quantization:

1. Non-final prefills for XPU Qwen GDN end on the absolute 64-token arithmetic
   grid. The ragged `[127, 4095, 4095, 127]`/8192-token case schedules 3968,
   rather than 3970, tokens for the partial third prompt and retains its final
   127-token tail. This policy applies to cache mode `none`, no speculative
   tokens, no multimodal support, and no encoder-decoder model. It rejects
   budgets below `64 + max_num_seqs - 1` and positive thresholds below 64 to
   avoid starvation. Internal checkpoint support cannot bypass this grid.
2. For ordinary mixed non-speculative batches, the Python adapter selects the
   native `split_mixed_non_spec` path only with one token per decode, exact
   non-spec token totals, no spec rows, no token indirection, and no spec mask.
   Kernel k04 then processes cached decode separately, preserving its ordinary
   recurrent arithmetic instead of the Xe2 prefill implementation.

`QWEN_GDN_ATTN` scopes these requirements and is also consumed by the later
KVarN request-stability policy. Generic GDN, non-XPU platforms, speculative
requests, and multimodal scheduling must retain their existing behavior.

The old deployed profile is Arc Pro B70, Qwen3.8-27B-INT4, BF16 compute,
K4V2 target/draft, MTP2 and vision. That profile does not activate the optional
no-spec/non-multimodal grid. The retained mixed adapter can still handle any
eligible ordinary batch, but the V2/DFlash verification rows are not such a
batch. This requirement is retained supported behavior, not proof of an effect
on every request in the production configuration.

AST comparison confirms the native adapter is unchanged from this commit to
the final old tip. The scheduler splitter is **not** identical: v06
`81dc387cf9a80e88468b7f77f7df8dfb71939921` adds a resend checkpoint stop in
align mode. Its behavior belongs to the KVarN/prefix-cache feature and must be
reconciled with v0.32's now-changed checkpoint helper, rather than accidentally
copied back over it. v05 changes pool-qualified zeroing nearby, not this grid.

- `7e583e615c20ee4ff0cd82aac592c7d6310aa7c3` (#59175) and

  `get_mamba_prefill_checkpoint_position` for the last cache position and tail

  Preserve those changes when reapplying the grid and reconcile v06's resend
  stop with them. These changes address align-mode cache semantics, not the
  mode-none arithmetic grid.
- `bd42276e1e25f540f019381c65994120158aa2a1` (#58457) validates rounded
  cache block sizes against every non-SSM backend. Preserve that validation

  minimal platform test fixture.
- `548597367e66dcc90e24576c08e0e25f88c9ee6c` (#57560) adds ROCm AITER
  prefill metadata/dispatch, not an XPU replacement.

MRV2-specific evidence: `gpu/model_runner.py::sort_batch_req_ids` places
