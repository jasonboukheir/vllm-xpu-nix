## Requirement and final-old behavior

The parent creates target attention groups containing registered draft layers
when their backend/spec/head grouping matches. `KVarNMetadataBuilder.build`
is stateful: it selects implementations by `_layer_names_set`, retags their
`_group_key`, mutates slot/sink dictionaries and GPU mirrors, then flushes
each implementation's `_kv_cache_ref`. Target and draft builders therefore
compete for the same draft implementations despite having separate
`_block_fill` and `_retired_sinks` shadows. Different target/draft sequence
positions make this a correctness defect, not redundant work alone.

v11 excludes only registered `KVARN` draft layers from V1
`GPUModelRunner.initialize_attn_backend`; its nested `getattr` handles
absent/None drafters. Physical `KVCacheGroupSpec.layer_names` remain intact,
and `LLMBaseProposer.initialize_attn_backend` constructs the draft's owner.
Five regression cases cover present/None/absent drafter and ordinary-backend
controls. The affected runner code is unchanged between v11 and the released
tip; later repairs do not supersede ownership isolation.

Preserve the released B70 RedHat W4A16/BF16-compute workload with K4V2 target
and MTP2 draft, four slots and two images. The required V2 syvai DFlash2
configuration also needs exclusive owners for both compressed caches.

## Upstream coverage

Upstream `39474513f6631b1bc39a2400126bd7ff9394a774` introduced
`gpu/attn_utils.py:init_attn_backend(active_layer_names=...)`. At the frozen
target, `DraftModelSpeculator.set_attn` uses that filter for draft builders.
`GPUModelRunner.initialize_kv_cache` computes `target_attn_layer_names` but
passes it only to other checks; its initializer receives `draft_layer_names`,
which controls fast-prefill eligibility, not ownership. Thus upstream supplies
the filtering primitive, not this invariant.

The target contains no KVarN implementation. TurboQuant's per-token packed
storage (`TurboQuantAttentionBackend.customize_spec`) is not a replacement for
KVarN's tile flush/tail allocator. Upstream
`5fe77aecfc7687c1f3cc49862022ce34d45d1784` removes deprecated CPU sequence
shadows, but does not provide exact KVarN committed-history ownership.

## Minimum residual and caller reconciliation

**ADAPT, folded into v05's V2 KVarN implementation.** Reuse the existing
active-layer filter and preserve physical allocation membership. Retain the
narrow V1 exclusion wherever that runner remains supported; do not restore
V1 as the requested implementation.

1. **MTP prefill requires an accompanying change.**
   `gpu/spec_decode/autoregressive/speculator.py:propose` passes target-built
   `attn_metadata` directly to `_prefill`; `capture` uses
   `target_attn_groups` for that first draft step. Filtering draft layers
   without rebuilding their prefill metadata leaves required entries absent.
   Have the dedicated draft owner build compressed MTP prefill metadata with
   the correct batch inputs, then reuse that owner for later draft steps.
   Preserve ordinary-backend reuse, or explicitly migrate its callers too.
   `ExtractHiddenStatesSpeculator.propose` also indexes draft names in target
   metadata, so an unconditional all-backend exclusion is not a safe cleanup.
2. **DFlash ordering remains separate.** Its `propose` inserts context K/V
   before `_build_uniform_attn_metadata`. The draft owner must reserve slots
   before insertion and distinguish committed context from speculative query
   writes/rejection. `dummy_run` supplies `context_slots=None`, avoiding the
   context write, but still builds query metadata; that builder must not
   reclaim real ownership from placeholder block tables. Keep graphs,
   adaptive verification and prefix caching outside initial qualification.
3. **Physical consumers still need every cache.** V2 `_init_kv_zero_meta`
   enumerates only `self.attn_groups`. After ownership filtering, include
   draft groups in physical zeroing without creating another mutable owner.
   Keep allocation/binding/slot mappings complete and resolve kernel block
   sizes consistently for draft-only groups. Do not confuse intentional
   physical sharing with permission to share mutable lifecycle builders.
4. **Reset all applicable shadows.** Existing
   `KVarNAttentionImpl.reset_process_state` runs before full worker model load,
   clearing the registry, allocator maps, mirrors and bound-plan generations;
   preserve that whole-model boundary, never reset between target/draft loads.
   V2 `shutdown` and `_teardown_profiling_state` call
   `clear_layer_kv_caches`, which clears scale views but not KVarN
   `_kv_cache_ref`, tail pools or class state. Retained-model reinitialization
   needs cache/state invalidation with implementation registration preserved;
   blindly invoking the full reset loses `_all_impls`. Clear corresponding
   builder fill/retired-sink shadows when replacing ownership. Keep graph
   profiling guarded until temporary-cache teardown is covered.
5. **Profiling and batching must obey ownership.** `profile_run` uses
   `_dummy_run(skip_attn=True)`; lazy KVarN pools still require memory
   accounting and correct subsequent binding. Test dummy-to-real transitions.
   Shared initialization creates one builder per microbatch; multiple builders
   must not independently reclaim one allocator. Guard unsupported overlap
   until its ownership protocol is qualified.
