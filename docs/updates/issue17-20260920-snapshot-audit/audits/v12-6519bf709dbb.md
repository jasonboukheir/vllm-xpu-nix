## Physical allocation and ownership

Independently traced final-release `get_kv_cache_groups`,
`get_kv_cache_config_from_groups`, `_plan_kv_cache_tensors` and
`worker/utils.py:allocate_kv_cache`. The KVarN-plus-Mamba branch bypasses page
size unification. Each resulting group receives a physical pool, backing
buffer and local block-ID namespace. Compatible layers within one group share
the block table but occupy separate layer-strided bytes. Mixed K4V2/K4V4
specifications do not merge; their record widths and quantization modes differ.
This is not permission to alias target and draft cache contents.

Whole buckets preserve allocated bytes and capacity because per-block costs
sum each layer's actual page size; recurrent reservations and each layer's
null-page bytes remain charged. v12's test compares those outcomes against
the previous grouping, including matching-format controls. It adds no new
pool schema or kernel ABI; it makes v05's existing independent allocation less
fragmented in scheduler groups and metadata builders. No isolated speedup is
established by the grouping reduction alone.

Physical grouping and mutable ownership remain distinct. Matching target and
draft layers may share a physical group while requiring separate metadata
owners. The released builder keys state by its exact layer-name set.
Preserve v11's exclusion/filtering invariant and actual draft prefill metadata;
whole-bucket grouping cannot substitute for it. See the v11 report for V2
MTP/DFlash ordering and reset details.

## Upstream coverage and final-old changes

Neither frozen tree contains KVarN/K4V2. Upstream already supplies useful
per-layer machinery: V2 `gpu/attn_utils.py:init_attn_backend` unwraps
`UniformTypeKVCacheSpecs` and groups by backend, layer specification and query
head count. It still needs KVarN's spec-local policy; base
`DraftModelSpeculator.attn_vllm_config` returns target configuration, so simply
assuming every builder sees draft dtype is incorrect.

Upstream `d43bb2f37f87a63d3a9a299c97050443cf6a2520` introduces HiSparse;
`e19a3e172ecc1d1ece8ecce9dfd91bf811a814a0` adds shared TP host storage.
`hisparse/layout.py:get_hisparse_kv_cache_groups/get_hisparse_kv_cache_config`
and `gpu/attn_utils.py:init_kv_cache` provide specialized sparse-MLA
host/device allocation. `KVCacheConfig.num_blocks_of` distinguishes host from
device, while ordinary `allocate_kv_cache` still creates one device backing
buffer. These do not replace independent KVarN device pools. Preserve upstream
host placement, group roles, transfer flags and specialized initialization
when extending backing identity and capacity lookup.

The frozen `_get_kv_cache_groups_uniform_page_size` retains compatible-bucket
merging followed by equal-size splitting; no independent-pool bypass exists.
`d29c88f162a3ec17ddb0afdf5f4f3b3ca6b84d59` adjusts SWA block-size selection,
not this grouping policy. TurboQuant's per-token packed allocation likewise
does not implement KVarN's records or mutable history.

Final-old v15 `2e010408b9713dca3de690f339ef46fbe72f090f` only extends this
admission expression to explicit `bfloat16` drafting with K4V2 target. It
retains v12's K4V4 admission, group-local selection and grouping unchanged.
`auto`/`bf16` remain rejected by this compact contract. v13 repairs reservation
overrides; it does not supersede v12.
