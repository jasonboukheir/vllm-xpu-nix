## Requirement and final old-stack behavior

The original workaround changed only `vllm/model_executor/models/registry.py::_run`. After executing an inspection callback and closing its pickled result file, an XPU child flushed stdout/stderr and called `os._exit(0)`. Its recorded purpose was to prevent Python/Torch shutdown from looking up an uncached operator after native registry destruction, producing garbage overload names, Unicode decoding failures or SIGSEGV. `_run_in_subprocess` otherwise treats nonzero exit as a failed inspection and aborts model startup despite a successfully written result. This is a lifecycle/startup requirement, not a decode speed optimization.

The relevant setting is model inspection that imports XPU native operators on Brutus; it is not specific to one cache dtype, draft method, runner version or quantization. The goal's new DFlash2 inspection must still succeed with a fresh cache. The old release already uses normal teardown: v06 deletes all 14 lines added by v01. Its commit records nine cold inspections, four real failure paths, and successful cold 27B server health/generation on Brutus. `docs/releases/xpu-v1.8.0.md` explicitly records the retirement in the released source pair, with Torch unchanged. These are historical recorded results, not tests newly rerun here.
