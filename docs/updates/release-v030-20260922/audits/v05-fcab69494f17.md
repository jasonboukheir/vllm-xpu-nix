## Target-specific coverage and differences from the prior snapshot

Neither selected target contains KVarN implementation. Inspection of the
alternative implementations supports retaining the feature:

- vLLM `TurboQuantAttentionBackend.customize_spec` uses per-token TurboQuant
  slots and `LBNHC`, not KVarN group records, `LBHNC`, Sinkhorn and mutable
  resident-tail flushing. Its target blob remains
  `8542e6164f0303a618194b45f4b7efd054a5a0a1`, identical to the previously
  inspected old/snapshot blob. It is not a K4V2 replacement.
- Ordinary `get_kv_cache_config_from_groups` still creates a shared device
  backing/count. HiSparse changes
  `d43bb2f37f87a63d3a9a299c97050443cf6a2520` and
  `e19a3e172ecc1d1ece8ecce9dfd91bf811a814a0` are included and add host/device
  sparse-MLA storage. They do not provide independent device attention/Mamba
  pools. `v1/hisparse/` has no diff against the prior snapshot; registry
  differences there are docstring formatting, with role lookup still present.
- `5fe77aecfc7687c1f3cc49862022ce34d45d1784` is included. It removes
  `CommonAttentionMetadata._seq_lens_cpu`, `.seq_lens_cpu`,
  `._num_computed_tokens_cpu` and `.num_computed_tokens_cpu`, including
  corresponding V1 proposer copies/increments. This affects **V1** replay,
  not just the paused V2 work.
- Target V1 `_prepare_inputs` computes `optimistic_seq_lens_cpu` assuming
  all drafts were accepted; `_build_attention_metadata` passes it as
  `seq_lens_cpu_upper_bound` alongside live device `seq_lens`. The field's
  contract explicitly disallows using the optimistic bound as an exact
  async-spec context length. KVarN must not permanently quantize rejected
  history by treating that bound as committed length.
- The release tag lacks snapshot-only `max_num_active_seqs`,
  `num_prefill_lookahead_tokens`, bounded-replay fields and later device-ID
  placement code. Use the target's APIs. Do not copy those unrelated snapshot
  additions while resolving conflicts. Existing `max_num_seqs` remains the
  recurrent reservation dimension.
- Target `AttentionImpl` gains explicit context-parallel compatibility checks
  through `db3814a4f215e666098ffb74a5c21bf46c60bae9`. Preserve them and the
  current TP1/PP1 limits; do not invent KVarN DCP support.
- Companion release v0.1.15 differs from the prior snapshot kernel target in
  GDN code/tests. The previous conclusion about upstream ragged-rollback
  coverage is not transferable by assumption; its owning audit must decide.
  The KVarN native operators remain a paired local requirement at this tag.

**Disposition: ADAPT**, folding the final released repairs into one coherent
owning feature. Upstream does not cover the required representation,
independent pools or cache lifecycle. No runtime deletion is justified by a
conflict, a missing test run, or different naming alone.

## Minimum V1-preserving replay instructions

1. **Retain the existing execution contract.** Keep KVarN's V1 selection and
   explicit V2 rejection in `config/vllm.py`, `platforms/xpu.py` and
   `xpu_worker.py`; retain eager/graph/prefix/geometry guards. Restore final
   concurrent MTP and target/draft dtype admission, not the original B1 rule.
   Preserve deterministic oneDNN setup and current-stream native dispatch.
   Add no D128, DFlash, draft-window or V2 ownership implementation.

2. **Adapt exact V1 metadata, with v16's owner.** Preserve
   `CommonAttentionMetadata.block_table_cpu`, its unpadding/derived-metadata
   propagation, and `_block_table_cpu_view` from the authoritative live rows
   of `BlockTable.get_numpy_array` (still present at this tag). Reconcile
   KVarN `build`/materialization users of removed CPU length fields with
   exact live device lengths, or a scoped exact CPU shadow copied and
   invalidated correctly after rejection and each draft increment. Never
   substitute the optimistic bound. Avoid reviving the entire deprecated
   upstream API just for convenience. Preserve v16's independently advanced
   alias/overlap semantics wherever a CPU shadow remains. Measure any new
   host synchronization as a potential regression against the released V1
   path; correctness takes precedence over eliding a synchronization.

3. **Preserve V1 owner separation.** Fold v11's narrow exclusion of registered
   KVarN draft layers into target
   `GPUModelRunner.initialize_attn_backend:get_attn_backends_for_group`, while
   leaving physical group membership and ordinary-backend metadata reuse
   intact. Keep `LLMBaseProposer.initialize_attn_backend` as the draft owner
   and use actual group quant mode/geometry for its lifecycle policy. Do not
   confuse separate mutable ownership with separate layer storage or with
   permission to alias target and draft contents.

4. **Integrate device pools without overwriting HiSparse.** Add pool identity
   and capacity to `KVCacheTensor`/`KVCacheConfig`, retaining host placement,
   roles, transfer flags, `kv_cache_layout` and all `hisparse_*` fields.
   Extend the existing `num_blocks_of(tensor)` so independent **device**
   tensors use their own count while host tensors retain
   `hisparse_host_num_blocks`. `allocate_kv_cache` must select each pool's
   backing and count together, retaining `spec.has_layer_views` raw-backing
   handling and ROCm allocation behavior. HiSparse
   `allocate_hisparse_kv_caches` passes a shallow device-tensor-only config
   copy to that helper and separately creates host views: preserve that path.

5. **Preserve grouping/projection and role dispatch.** Retain early HiSparse
   grouping/planning dispatch. Apply the KVarN no-page-unification and whole
   compatible-bucket branch only to independent device groups. Target
   `_project_kv_cache_groups_to_worker` currently reconstructs a group with
   names/spec/`is_eagle_group`, while the old local patch preserves transfer
   only. Resolve this with field-preserving projection so `host_resident`,
   `enable_kv_transfer` and `role` survive, retaining filtered per-layer specs
   and stable empty group slots. Keep
   `get_manager_for_kv_cache_spec(..., role=group.role)`,
   `KVCacheSpecRegistry.get_manager_class(spec, role)`, role registrations,
   and `HiSparseCoordinator`'s host-pool binding. Existing KVarN quant-mode
   additions do not require a new spec class or replacement registry.

6. **Fold one consistent reservation policy.** Consolidate v08/v13 accounting:
   Mamba demand follows the actual spec times `max_num_seqs`; attention
   admission/auto-fit uses one full-context capacity unit and the independent
   override multiplies attention demand only; charge each pool's null storage
   once. Use actual mixed-format layer groups. Retain HiSparse memory/probe
   branches, ordinary physical-block override semantics, and per-pool worker
   minima/stride replanning. `generate_scheduler_kv_cache_config` must compare
   pool topology/counts as well as preserve host-capacity checks. Equal
   attention token capacity is still the released MTP policy; no new bounded
   draft allocation category is requested here.

7. **Carry every pool-qualified consumer.** Preserve block `pool_id`,
   `KVCacheBlockCopy.group_id`, per-pool admission/watermarks and scheduler
   zero descriptors. Adapt V1 `_init_kv_zero_meta`,
   `_zero_block_ids_by_group`, `zero_mamba_block_ids` and
   `copy_kv_cache_blocks_inplace` together. Verify physical draft caches are
   included where necessary after mutable-owner filtering. Preserve CPU
   runner behavior and compatible V2 shared-helper call signatures where the
   feature touches common code; this does not enable V2 KVarN. Keep upstream
   manager-owned event/reset/cache-hit paths and `BlockPool` reuse/unpin
   callbacks. Retain narrow unsupported-connector checks for independent
   KVarN pools, without classifying ordinary HiSparse host/device storage as
   those pools.

8. **Retain memory/lifecycle ownership.** Keep worker whole-model
   `reset_process_state` before loading the replacement model, never between
   target and draft construction. Materialize lazy tails/scratch inside the
   measured memory-profile window once, without a second arithmetic charge.
   Target V1 `shutdown` calls `_cleanup_profiling_kv_cache`; that helper clears
   layer caches and scale views, not local KVarN `_kv_cache_ref`, allocator
   maps or `_all_impls`. Test shutdown/reload and any reachable same-model
   cache replacement. If a retained-model replacement is supported, invalidate
   cache bindings/shadows while preserving implementation registration; do
   not blindly use whole-model reset at that boundary. Keep graph profiling
   guarded and v14's serial bounded-scratch reuse semantics.
