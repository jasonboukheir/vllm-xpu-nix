## Requirement and effective released behavior

When scheduling or context limits shorten a speculative query, current token count must not replace retained rollback capacity. For MTP2, capacity is three although a request may execute one or two tokens; the previous step may have accepted all three. The pre-k06 interface requires rectangular token count, and both speculative kernels address tokens as `batch_id * capacity + t`. Ragged requests therefore either fail validation or traverse incorrect compact token positions.

k06 traverses each request's `query_start_loc` slice, gathers/scatters through `token_indx`, reads convolution history and the recurrent slot selected by previous acceptance, writes only executed-token states, and leaves unused capacity intact. It adds `test_gdn_shortened_mtp_preserves_rollback` in `tests/gdn_attn/test_gdn_attn_padded.py`. The 24 parameter combinations cover lengths `(2,)`, `(1,)`, `(3,2,1)`, acceptance 1/3, both projection layouts and geometries `(4,8,32)`/`(16,48,128)`, using BF16 computation and FP32 recurrence. The latter geometry matters to the Qwen target on Arc Pro B70. All four touched files are unchanged between k06 and the final kernel release; later KVarN/release commits do not supersede its behavior.

## Exact upstream replacement

The entire old-base-to-target history under `csrc/xpu/gdn_attn` contains one upstream change: `da16a5595c105605bcd44b558c7933b934a05f85`, “Fix ragged speculative token traversal” (#600).

- `causal_conv1d.hpp:causal_conv1d_spec_kernel`, target lines 620–825, receives `query_start_loc` and uses actual request ranges for b/a, z, q/k/v and rollback writes. Let convolution width be W, retained token capacity C, current length L and previous acceptance A. Upstream keeps physical effective length `W-2+C`, then writes logical length `(W-2+C)-(C-L) = W-2+L`; k06 directly names `W-2+L` as `state_len`. Both retain `W-2` historical rows, read the initial window beginning at `max(A-1,0)`, and leave the same tail untouched. Neither truncates that initial read when A exceeds current L. Stride remains an address stride, not a substitute for logical length, so interleaved layer allocation remains valid.
- `gated_delta_rule.hpp:gated_delta_rule_spec_kernel`, lines 392–524, reads initial column `max(A-1,0)` using `cache_indices_stride_0`, iterates compact `token_start..token_end`, writes rollback column `t_local`, and scatters output through `token_indx[t]`. Thus C remains independent of L, with no writes to unused SSM columns.
- `gdn_attn_interface.cpp:causal_conv1d_spec`, lines 93–126, derives C from state-index columns, retains the full convolution allocation requirement, and accepts positive total tokens bounded by aggregate capacity. `gdn_attention` invokes these same convolution/recurrence functions at lines 818/841, so coverage applies to the fused operator used by vLLM, not only separately exposed operators.

There are diagnostic differences: k06 additionally checks total tokens ≥ request count and device-asserts `0 < L <= C`. Upstream lacks these checks. They do not change supported positive, capacity-bounded request behavior; neither implementation fully validates device cumulative offsets. Do not claim identical malformed-input rejection or reintroduce these checks as another rollback implementation. Active-row validity must remain a metadata contract, with padded requests removed by v02.

The alternate Triton `causal_conv1d_update` at frozen vLLM `vllm/model_executor/layers/mamba/ops/causal_conv1d.py:844–876,1219` independently uses the same capacity-minus-unused-length rule and accepted-history offset. XPU still executes Qwen `forward_xpu` → `_xpu_ops.py:_gdn_attention_core_xpu_impl` → native `gdn_attention`; Triton is corroborating semantics, not an assumed XPU fallback. V2 `MambaHybridModelState.prepare_attn` passes accepted counts and draft classification to `GDNAttentionMetadataBuilder.build`, which retains full state columns and constructs compact cumulative query lengths. The selected vLLM changes do not replace native rollback.
