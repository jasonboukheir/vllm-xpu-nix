## Requirement and surviving behavior

MTP2 retains three rollback columns even if scheduling or the context limit shortens the next speculative verification to one or two tokens. Previous acceptance may still be three. Per-request executed length must determine token traversal and new state writes; retained capacity must continue to determine available previous rollback state.

k06 makes both native speculative kernels traverse `query_start_loc[batch_id:batch_id+2]`, gather/scatter using `token_indx`, preserve previous-acceptance selection, and leave unused state capacity unchanged. With convolution width W, retained capacity C and current length L, allocation remains at least W−2+C rows, while writes cover W−2+L rows. The initial history read still begins at `max(previous_acceptance−1, 0)`; shortening L must not clamp that read to L. The recurrent kernel loads the previous accepted column, writes only columns `0..L−1`, and keeps unused columns intact. Interleaved convolution layer strides remain address strides, not logical lengths.

The commit touches three native files and adds `test_gdn_shortened_mtp_preserves_rollback` to `tests/gdn_attn/test_gdn_attn_padded.py`. All four files are byte-identical between k06 and final released kernel tip `2c39287d`; subsequent KVarN/release commits neither replace nor revert this requirement.

## Minimal retained delta and dependencies

Retain k06 as one independently useful rollback correctness commit, including its three production files and regression. No additional public operator, schema, dtype or dispatch change is required: cumulative query pointers already reach the host launchers; k06 forwards them to the internal speculative kernels. There is no reason to fold it into KVarN or add another implementation of #600 alongside it.

- v02 `cf0b834cd66c54156393e2f943382b1015360f84` remains separately responsible for live-request slicing/padding normalization. k06 expects active rows to satisfy `0 < L <= C`; zero-length padded rows are not valid speculative requests.
- Paired v03 `7de1e1c5ec5f3005b0e46bb0ec323f5e5864876c` / k05 `9e2ac704b8627e2fd8d37c42f769e615cfc1f122` supplies mixed ordinary prefill/decode arithmetic and its public trailing `split_mixed_non_spec` keyword. k06's pure-spec regression currently supplies `split_mixed_non_spec=False`, so the saved test assumes that schema. Omitting that irrelevant keyword permits an upstream-only negative control without accidentally failing first on an unknown keyword. Do not remove k05's needed production behavior merely to simplify this test.
- k03 `32f42475774852d7174fe6cd9f8201878603381f` changes non-spec convolution. It shares a file, not this speculative-state requirement. Preserve parent reconciliation of k03/k04 independently.
- k06 does not establish KVarN committed-history correctness, cache ownership, reset correctness or vision support. Those release gates remain separate.

The existing positive-length aggregate checks and device assertions are adequate to retain the supported contract, but are not comprehensive hostile/malformed offset validation. This audit makes no claim that arbitrary inconsistent metadata is safe.
