## Requirement and effective old behavior

An explicitly configured `float16` or `bfloat16` native XPU KV cache must work
when key, value, key cache, and value cache all have that exact dtype. Native
dispatch spells input-matching storage `auto` and otherwise rejects the
literal names. The local wrapper checks all four tensor dtypes and translates
only its native-call argument. It neither converts tensors nor changes the
engine configuration. Keeping configuration explicit matters because checkpoint
FP8 metadata is allowed to override `auto`.

Brutus's released K4V2 target/draft profile does not exercise this ordinary
cache writer, but explicit unquantized controls and a K4V2 target with a BF16
drafter do. The requested V2/DFlash migration makes the latter configuration
especially relevant. Later local commits v05–v08 change neither file touched
by v04, so its implementation and tests retain their complete effect at the
old tip. There is no superseding local implementation or repair/revert pair.

## Disposition and dependencies

**KEEP** v04's existing fourteen-line guard/translation and its native tests
as one independent correctness commit. This is the minimum residual change.
Preserve the XPU device gate, all four exact dtype checks, and unchanged
forwarding for other devices, `auto`, and FP8. No source adaptation is required
for the frozen target wrapper.

There is no production prerequisite on its historical parent. The native
eight-argument operator schema in `csrc/torch_bindings.cpp:314` is unchanged;
no kernel schema or ABI addition is required. The optional BF16-draft path in
v05 (`ef92dc5600af64103c01f97e3300b81c3a1083ee`) and the proposed V2/DFlash
BF16 draft rely on this behavior. k07's KVarN writer is separate and does not
replace it. No other local commit needs folding into v04; keep it separate
from KVarN because explicit ordinary caches remain independently useful.
