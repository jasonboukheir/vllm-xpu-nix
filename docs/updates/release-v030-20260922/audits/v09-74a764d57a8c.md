## Requirement and effective old stack

Explicit `float16` and `bfloat16` caches must work through native XPU
FlashAttention when key, value and both cache tensors have that exact dtype.
The native writer spells this input-matching mode `auto`, but the engine's
explicit selection must remain intact: changing the configuration to `auto`
can accept an FP8 cache scheme from the W4A16 Qwen checkpoint. The fix guards
all four tensor dtypes before translating only the native call argument.
Otherwise the native template can reinterpret incompatible input/storage
buffers. It performs no conversion and admits neither mixed FP16/BF16
storage nor additional aliases.

The final old release retains v09's production function unchanged. v15,
`2e010408b9713dca3de690f339ef46fbe72f090f`, adds explicit BF16 MTP draft
admission and independent paged-attention references; it depends on this
writer behavior rather than superseding it. Existing K4V2 target/draft MTP2
uses its separate compressed writer, but retaining prior supported native
cache configurations remains part of this release's scope.

## Disposition, dependencies and folds

**KEEP** the original fourteen-line guard/translation and sparse-write
regressions as one independent correctness commit. It has no local
production prerequisite despite its historical parent. Leave CUDA/ROCm,
`auto`, FP8 and KVarN outside the branch; preserve engine configuration and
all four dtype guards. There is no reason to add a kernel schema, broaden
configuration admission or bury this fix in the KVarN feature commit.

Fold v15's independent
`test_bf16_draft_paged_attention_matches_independent_causal_reference`
additions into this commit, preserving attribution. Its admission, backend
isolation and heterogeneous allocation tests belong with their KVarN owner.
The twelve reference cells cover D256 Q24/KV4, batches 1/4, query lengths
1/3/129, permuted physical pages and finite padding 0/123. They compare to
FP32 SDPA with an explicit bottom-right causal mask and check speculative
tail overwrite/restore.

Those numerical references must forbid
`vllm_xpu_kernels.flash_attn_interface._fallback_varlen_attn`. At the selected
kernel target, lines 620–653 catch a native `not compiled` error and invoke
that reference fallback. A passing numerical test alone cannot prove the
required native policy was compiled. Add/retain a negative control proving
the forbidden-fallback check fires. This is test strengthening, not a new
production implementation or a BF16 serving milestone.
