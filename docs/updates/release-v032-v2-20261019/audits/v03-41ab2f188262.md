## Requirement and effective old-stack behavior

The XPU residual form of `rms_norm_batch_invariant` must leave input, residual
and weight unchanged; return two separate outputs; normalize the unrounded
FP32 input-plus-residual sum; and return the sum rounded to activation dtype as
the residual output. The fixed 1024-column reduction blocks keep a given row
independent of other batch rows, including the native launch's 256-row boundary.
The retained cases cover FP16/BF16 activations, absent/same-dtype/strided FP32
weights, strided inputs, and higher-rank shapes. Non-XPU residual calls continue
using their existing native fusion.

The assigned production/test files are byte-identical at the assigned commit
and full old main: no later repair or revert supersedes this contribution.
v05 `ef92dc5600af64103c01f97e3300b81c3a1083ee` adds the scoped consumer in
`GemmaRMSNorm.forward_native`, via `request_invariant_apply_once` and
`apply_rms_norm_by_request`, and bypasses XPU Gemma fusion for scoped slices.
`determinism/request_stable_linear.py:_is_xpu_kvarn_request_stable_profile`
restricts that consumer to the exact AEON W4A16/BF16 revision, compact K4V4/K4V2,
eager V1, no prefix caching/speculation, language-only, and restricted
parallelism. It explicitly returns false for V2. The current RedHat profile and
planned V2/DFlash2 profile do not activate it. Neither the user nor this audit
retires that optional supported behavior.

## Disposition and dependencies

**KEEP** the XPU-only residual branch, fixed-tree Triton kernel and two appended
tests as one independently useful correctness commit. Preserve all v0.32
determinism additions and CUDA/ROCm test decorator changes. There is no required
source adaptation for this helper, no native ABI/schema addition, and no
dependency on parent v02 despite commit ancestry. Kernel deterministic W4A16
matmul does not implement RMSNorm determinism.

v05 owns the optional Gemma caller and selection policy, so its replay must
retain their contract if that optional profile remains supported. No v06-v08
RAM/prefix repair needs folding into v03. Do not enable or broaden the scoped
V1 policy for V2 as an incidental part of replay. Explicitly retiring the scoped
behavior and direct helper contract could change the disposition, but their
inactivity on one production profile alone does not justify deletion.

## Validation observed and still required

Observed in this audit:

- Stable patch ID and parent matched inventory; candidate HEAD matched target.
- Exact assigned-file diff through old main and kernel layernorm base-to-tip
  diff both empty.
- A stdlib-only probe executed with the candidate `.venv/bin/python` compared
  ASTs and executed the extracted actual helper bodies against lightweight
  tensor/kernel test doubles. Both upstream AST comparisons passed. Six
  control-flow cases passed: optional/present weights for upstream XPU (native
  dispatch and argument aliasing), old-fork XPU (separate allocations,
  257-row grid, fixed 1024 block, correct weight flag), and old-fork non-XPU
  (native dispatch/argument identity preserved). This establishes dispatch and
  allocation control flow, **not numerical correctness or device execution**.
- No installed-package, GPU, numerical, service, latency or model test ran.
  The prior audit records historical direct-helper passes and a separate
  optional AEON whole-model concurrent-token invariance failure on both the
  baseline and candidate; this audit does not turn that broader failure into
  a pass.

Required after replay and package build:

1. Run `test_xpu_residual_rms_norm_is_functional_and_batch_invariant` with
   global invariance disabled: 24 parameter cases, each checking rows
   1/4/255/256/257/300. Require executed cases rather than skips, exact
   unchanged inputs, independent outputs, FP32-add reference agreement, and
   same-row bitwise equality across batch sizes. (The previous audit's count
   of 48 was incorrect: 2 widths x 2 dtypes x 3 weight modes x 2 stride modes
   is 24.)
2. Run `test_non_xpu_residual_rms_norm_preserves_native_dispatch`; preserve
   upstream CUDA/ROCm coverage and report unavailable hardware honestly.
3. In a separate globally initialized process, run upstream XPU residual-layer
   cases and quantized-configuration rejection cases. Do not turn global
   invariance on in W4A16/KVarN serving to satisfy these tests.
4. Confirm the retained scoped caller and its V2 exclusion, then qualify the
   actual V2/DFlash2 model configuration through the parent's full suite.
   That suite is separate from any optional AEON invariance claim.

No performance gain is asserted. Replacing the fused helper with a composition
of FP32 temporaries and the no-residual kernel could reduce source code, but
changes launches, allocation and potentially rounding; it would need its own
correctness and matched latency evidence and is not part of this disposition.
