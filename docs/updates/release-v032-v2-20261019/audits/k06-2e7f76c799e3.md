## Requirement and final old-stack behavior

The sole change is the 223-line
`tests/flash_attn/test_flash_attn_determinism.py`. Its three test functions
expand to five BF16 cases with 24 query heads, four KV heads and head dimension
256: dense causal prefill lengths 104, 107 and 162, paged causal prefill length
162, and one-query paged decode with 162 cached tokens. Paged cases use page64.
These are recorded Qwen/KVarN investigation shapes, not a generic coverage claim
for every head configuration.

Each case first checks finite output and an independent CPU FP32 reference at
`rtol=1e-2, atol=2e-2`, then compares eight subsequent executions bit for bit in
BF16. Replays interleave different same-shape attention inputs, an allocation
whose size changes between iterations, and allocator cache release. The autouse
fixture replaces `_fallback_varlen_attn` with a failure, so an absent native
kernel configuration cannot silently pass by running reference attention.

This detects execution-order/allocator-dependent native output, while the
reference prevents a consistently wrong output from passing replay alone.
It does not assert whole-model output invariance across scheduling shapes.
The later KVarN commit `dbb684f4c9b38a8b3bbf52bda0c490ee47049221` leaves
this file unchanged. There is no local revert or repair to fold into k06.

The selected kernel old-to-new upstream range is empty: the base is retained
because vLLM v0.32.0 pins kernel wheel `0.1.15.4`. At that exact base:

- `tests/flash_attn/test_flash_attn_varlen_func.py::ref_paged_attn` remains the
  independent reference helper. Its broad tolerance/reference tests do not
  contain the local repeated exact comparisons, interleaved allocator pressure,
  or fallback-rejection fixture. A search of upstream `tests/flash_attn` for
  `bitwise`, `torch.equal`, `deterministic`, and `_fallback_varlen_attn` found no
  matching test replacement.
- `vllm_xpu_kernels/flash_attn_interface.py:423::flash_attn_varlen_func` accepts
  all arguments used by the local tests. All five cases reach the native
  `torch.ops._vllm_fa2_C.varlen_fwd` branch: their query lengths are either one
  or greater than the small uniform speculative-query fast-path bound.
- The wrapper still catches native missing-configuration failures and invokes
  `_fallback_varlen_attn` at line 640. The local rejection fixture therefore
  remains correctly targeted. The wrapper and imported reference file are
  byte-identical between the selected kernel base and final fork tip.

The companion update does not remove this API. At frozen v0.32.0,
`vllm/v1/attention/backends/fa_utils.py:30-36` binds the XPU backend to
`xpu_ops.flash_attn_varlen_func`. `FlashAttentionBackend` and

`f147949be8b9e576f80133bee01e717ee7c5db0e` adds the XPU
`MultipleOf(64)` supported-block-size constraint at
`vllm/v1/attention/backends/flash_attn.py:355-359`; it agrees with this test's
page64 and does not provide replay coverage. Cascade-attention removal
`e1a5086256a00c47a968aac6a583c25d040100a7` does not replace the native wrapper
or these direct native regression tests.

The new runner class remains an XPU specialization of GPUModelRunnerV2 at
`vllm/v1/worker/xpu_model_runner.py:29`. DFlash2 inherits the DFlash speculator,
whose model uses `DFlashQwen3Attention` and per-layer causal/sliding-window
selection in `vllm/model_executor/models/qwen3_dflash.py:123-180,260-272`.
The planned drafter's Q32/KV8/D128, noncausal sliding2048 execution is outside
this commit's five causal Q24/KV4/D256 probes. Likewise, eight-query target
verification, c4, prefix restore, images and 262K context require separate
qualification. Their addition must not be claimed as coverage supplied by k06.

## Dependencies and minimal delta

upstream reference helper and public kernel wrapper, adds no custom operator,
schema or ABI, and has no prerequisite on KVarN despite its original motivation.

fallback fixture intentionally exposes a reduced build missing those policies.
No cross-repository companion patch is required specifically for k06, and it
should remain separate from the native KVarN feature. Preserve existing author,
coauthor and sign-off if replay is necessary; retaining the unchanged kernel tip
retains the original commit directly.
